## 2. GMC Excel investigation (verified)
- **Formula cells cannot be edited:** crafted saves against formula cells return `422 formula_cell`; a wrong fingerprint returns `409 fingerprint_mismatch`; no input control is rendered for them; saved versions keep them locked.
- **Why INCOMPLETE:** see defect 1. It was a parser gap, not a real unknown dependency (both references of the RFQ formula were parsed correctly).
- **After the fix (end-to-end):** edit of an independent cell → `VERIFIED`, export HTTP 200; edit of a precedent cell (B19) → `INCOMPLETE` (stale cached results), export withheld (HTTP 409). Across the ledger only 8 of 127 edits are INCOMPLETE, all on genuine precedents (CAR-QCR B13, Fire QCR B13, GMC RFQ B28).
- **Recalculation recommendation (no verification weakened):** (1) keep INCOMPLETE and the download gate as they are. (2) If the stakeholder needs exportable precedent edits, add a *separate* outcome (e.g. `RECALCULATED`) that surgically updates only the cached `<v>` of dependent cells and is granted only when a second engine passes a **calibration gate**: forced recalculation of the *untouched original* must reproduce its own cached values. Measured with LibreOffice (forced recalc): exact on CAR-QCR, Fire QCR, Marine QCR, GMC RFQ (28 of 28) but **11 of 14 on GMC QCR** (Excel coerces date-like text where LibreOffice does not), so GMC would correctly stay INCOMPLETE. By default LibreOffice does **not** recalculate on load. (3) Alternatively an explicit, owner-authorised export of INCOMPLETE files carrying a visible banner and an audit event (policy decision). Not implemented here.
